StayPoint · STA-289 · Design proposal

See every step. Steer at any step.

Replaces the "working…" spinner with a live, expandable run timeline. One message starts the whole job; it still runs on its own, but every task, subtask, thought, command and edit stays visible, and you can pause or redirect it at the next clean step boundary.

1Timeline & transparencyNested tasks → subtasks → steps. Expand any step to see its thinking, command or edit.
2Interact & pauseMessage any time. "Pause after this step" stops at the next boundary, like Claude Code.
3Execution statsTotal and per-step time, files read and edited, lines added and removed, tokens, cost.
4Diff sidebarRight-hand diff on the full task page with per-file undo, like Claude Code's side panel.

Try it: click any row to expand it. Click an edit step to jump to its diff. Press Pause after this step or send a message to see how queued input behaves. The timer and the live step tick in real time.

What one step looks like on the wire

Every timeline row is one run.step event. The same record is saved to run_steps, so reopening a finished task replays the exact same timeline.

event: run.step
data: {
  "run_id": "r_8f2c", "task": "STA-312", "subtask": "STA-312.2",
  "seq": 23, "parent_seq": 18, "kind": "edit",           // think | read | run | edit | checkpoint | message | state
  "title": "Edit internal/server/events.go",
  "started_at": "2026-10-02T01:12:04Z", "ended_at": "2026-10-02T01:12:06Z",
  "status": "ok",                                       // live | ok | fail | waiting
  "detail": { "tool": "Edit", "path": "internal/server/events.go", "added": 18, "removed": 3 },
  "checkpoint": { "sha": "a41c9e2", "undo": "/api/checkpoints/a41c9e2/undo" }
}

"Pause after the next message", Claude Code style. A pause never cuts a command in half. It waits until the step that is running finishes, then holds the agent before it starts the next one. A message you type is queued and handed to the agent at that same boundary. Stop works like Ctrl+C in a terminal: press it once and the run wraps up cleanly at the next step boundary; press it again and it is killed right away. Either way a checkpoint is taken first, so nothing is lost.

Sequence: you pause mid-run, add a note, and resume

Run states

Shown as the pill next to the task title. "Stuck" is computed: no new step for N minutes while running.

Four ways to step in

Ordered from gentlest to hardest. Only the last one cuts work off.

ActionWhen it takes effectWhat happens
Send a messageNext step boundaryQueued, then given to the agent before its next tool call. The run keeps going.
Pause after this step EscWhen the current step endsThe current command finishes cleanly, a checkpoint is taken, and the agent holds until you resume or send a message.
Stop ⌃C (click once)When the current step endsSoft cancel. The current command finishes, a checkpoint is taken, and the run ends cleanly as stopped with a resumable session. Unlike pause, it does not wait for you.
Stop again ⌃C ⌃C (click twice)ImmediatelyHard cancel. Snapshots the working tree, then interrupts the CLI mid-step (SIGINT, then SIGKILL if it ignores it). Run marked stopped, still resumable.

No timers. Nothing interrupts after 30 seconds or 5 minutes. The only timer is the stuck warning, and it only warns.
